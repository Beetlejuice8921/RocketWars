# Rocket Wars — сервер рейтинга

Cloudflare Worker `rocketwars-api` + база D1 `rocketwars`. Бесплатного тарифа хватает с большим запасом.
Клиент в игре: `Assets/_Project/Scripts/Online/RatingApi.cs` (запросы), `MatchRating.cs` (отчёт о матче),
`UI/LeaderboardView.cs` (окно «Рейтинг» в меню) и строка рейтинга на экране итогов (`UI/ResultsView.cs`).

## Как засчитывается матч

1. **Вход.** Telegram: игра отправляет `initData`, сервер проверяет его подпись токеном бота и узнаёт настоящий Telegram ID.
   Остальные сборки (Steam, браузер вне Telegram, редактор) входят **гостем** по случайному ключу устройства:
   гость копит очки, но в общую таблицу не попадает и матчи не подтверждает.
2. **Старт.** Хост регистрирует матч (`POST /v1/match/start`) и раздаёт его id клиентам (`StatsNet._ratedMatchId`).
   Нет связи — матч просто без рейтинга.
3. **Конец.** Таблица итогов замораживается, и каждый живой игрок через 2 с отправляет её целиком (`POST /v1/match/report`)
   с пометкой «это моя строка». Сервер приводит таблицы к одному виду и сравнивает хэши.
4. **Кворум.** Итог принят, когда совпали отчёты `max(2, половина живых игроков)` аккаунтов Telegram.
   Очки получают те, кто прислал совпавший отчёт. Отчёт с другой таблицей — `rejected`.
5. **Тренировка.** Один живой игрок против ботов: подтверждать некому, поэтому +3 очка за матч и не больше 30 за неделю.

Защиты: строку бота и чужую строку занять нельзя; один отчёт на игрока; счёт должен быть 4:x; матч не короче
60 с (и 12 с на раунд); старше 3 ч — не принимается; хост регистрирует не больше 3 матчей в минуту.
Что остаётся возможным: сговор нескольких настоящих Telegram-аккаунтов (кворум их не отличит) — смотрим по таблице
`match_reports`, если начнутся подозрительные взлёты.

## Очки

| За что | Очки |
|---|---|
| Сыгранный матч | 10 |
| Победа | +20 |
| Положил врага | +2 (до 15 за матч) |
| Поднял союзника | +2 (до 10) |
| Взорвал шахту | +3 (до 10) |
| Награда матча | +5 за каждую |
| Положил своего | −2 (до 10) |
| Вышел до конца | 0 |

Недельная таблица (`season = 2026-W43`, неделя ISO) обнуляется в понедельник 00:00 UTC (03:00 МСК);
таблица «Всё время» (`season = all`) копится всегда. Одинаковые очки — одно место.

## API

| Запрос | Что делает |
|---|---|
| `POST /v1/auth` `{provider: telegram\|guest, data}` | токен на 7 дней |
| `POST /v1/match/start` `{platform}` | `{matchId}` (хост) |
| `POST /v1/match/report` `{matchId, me, score0, score1, winner, rows[]}` | `{status: pending\|credited\|rejected, points, weekPoints, rank, rankBefore, practice}` |
| `GET /v1/match/result?matchId=` | то же состояние (клиент опрашивает, пока `pending`) |
| `GET /v1/leaderboard?season=week\|all&limit=50` | `{season, resetsIn, top[], me}`; без токена — без `me` |

## Выкладка

```
powershell -ExecutionPolicy Bypass -File Backend\deploy.ps1
```

В первый раз скрипт создаст базу D1, запишет её id в `wrangler.toml` (закоммитьте), применит `schema.sql`,
выложит Worker, создаст секрет `TOKEN_SECRET` и спросит **токен бота** (`BOT_TOKEN`, из @BotFather).
Адрес сервера зашит в `RatingApi.DefaultUrl`: `https://rocketwars-api.tg-placeholder.workers.dev` —
если поддомен аккаунта поменяется, поправьте его там.

## Локальная проверка

```
cd Backend
copy .dev.vars.example .dev.vars
npx wrangler d1 execute rocketwars --local --persist-to .wrangler/state --file schema.sql
npx wrangler dev --persist-to .wrangler/state --port 8787
node test/smoke.mjs
```

Игра на локальный сервер: аргумент `-api http://127.0.0.1:8787` (или переменная окружения `RW_API_URL`).
В `.dev.vars` гости считаются как Telegram-аккаунты (`GUESTS_RANKED=1`), а длительность матча не проверяется,
поэтому можно проверить кворум двумя копиями dev-сборки на одном ПК: у каждой свой `-guestKey <32 hex>`.
